================================================================================
ОТЧЕТ ПО АУДИТУ БЕЗОПАСНОСТИ И УЯЗВИМОСТЯМ ORBITA MESSENGER
================================================================================

[ИСПРАВЛЕНО] 1. Zero-Click RCE через XSS в окне кастомных уведомлений (RAT Vector)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts, public/notification-window.html, electron/preload.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  В `electron/main.ts` окно `notifWindow` переведено на `nodeIntegration: false` и `contextIsolation: true`.
  Создан изолированный preload-мост `orbitaNotif`.
  В `public/notification-window.html` введена строгая фильтрация схем URL (только https://, http://, data:image/, orbita-media:), убраны инлайн-обработчики onerror, добавлено экранирование HTML и одинарных кавычек.

[ИСПРАВЛЕНО] 2. Запуск вредоносных бинарников без проверки при открытии файлов (1-Click RCE / RAT)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts, electron/downloads.ts, src/components/chat/FileMessage.tsx
- Статус: ИСПРАВЛЕНО
- Описание:
  В методы `orbita:open-file` и `downloads:open` внедрена строгая валидация `isDangerousExecutable` и `DANGEROUS_EXTENSIONS`.
  Исполняемые файлы (.exe, .bat, .cmd, .vbs, .scr, .pif, .lnk, .ps1 и др.) блокируются от прямого запуска через `shell.openPath` — вместо этого открывается папка проводника через `shell.showItemInFolder`.

[ИСПРАВЛЕНО] 3. Path Traversal при скачивании и бэкапе (Arbitrary File Write / Persistence)
--------------------------------------------------------------------------------
- Файлы: electron/downloads.ts, electron/main.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  В `saveToDownloads` и `orbita:saveBackupFile` имена файлов строго нормализуются через `path.basename`. Запись за пределы разрешенных папок заблокирована.

[ИСПРАВЛЕНО] 4. Небезопасное автообновление без проверки подписи и контрольных сумм (Insecure Update / RCE)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  Введена строгая проверка источника обновлений: скачивание разрешено исключительно с официального репозитория GitHub Releases (`https://github.com/orbitachat/orbita-desktop/releases/download/`), валидируется расширение `.exe` и имя файла.

[ИСПРАВЛЕНО] 5. Утечка локальных файлов через кастомный протокол `orbita-media://`
--------------------------------------------------------------------------------
- Файлы: electron/main.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  В обработчике `orbita-media` локальные пути теперь строго ограничены каталогами `app.getPath('userData')` и `app.getPath('temp')`. Попытка чтения системных файлов или файлов вне этих папок пресекается кодом 403 Forbidden.

[ИСПРАВЛЕНО] 6. Небезопасные обработчики разрешений Electron (Blanket Permission Grant)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  Безусловный возврат `true` в `setPermissionRequestHandler` и `setPermissionCheckHandler` заменен на строгую проверку ориджина. Разрешения выдаются только внутренним доверенным страницам приложения и только для необходимых возможностей (медиа, уведомления, полноэкранный режим).

[ИСПРАВЛЕНО] 7. Раскрытие мастер-ключа и приватных ключей E2EE в глобальном объекте `window`
--------------------------------------------------------------------------------
- Файлы: src/store/useAuthStore.ts, src/store/useChatStore.ts, src/store/authStoreRef.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  Глобальный объект `window.__ORBITA_AUTH_STORE__` удален. Все перекрестные зависимости переведены на изолированный локальный модуль `authStoreRef.ts`, скрытый от внешней видимости в DOM.

[ИСПРАВЛЕНО] 8. Отсутствие валидации URL в `orbita:fetchUrl` (SSRF)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  Внедрена функция `isSafeNetworkUrl`, блокирующая запросы к localhost, loopback, link-local (169.254.x.x) и приватным диапазонам адресов (10.x.x.x, 172.16-31.x.x, 192.168.x.x).

[ИСПРАВЛЕНО] 9. Ослабление изоляции процессов в Chromium
--------------------------------------------------------------------------------
- Файлы: electron/main.ts
- Статус: ИСПРАВЛЕНО
- Описание:
  Опасный флаг `disable-site-isolation-trials` удален из командной строки запуска приложения.

[ИСПРАВЛЕНО] 10. Санитизация контента в окне уведомлений
--------------------------------------------------------------------------------
- Файлы: public/notification-window.html, dist/notification-window.html
- Статус: ИСПРАВЛЕНО
- Описание:
  Удалены любые опасные подстановки строк в DOM, экранируются специальные символы HTML и кавычки.

[ИСПРАВЛЕНО] 11. 1-Click RCE через `orbita:openFolder` при передаче пути к исполняемому файлу
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 2674-2682)
- Статус: ИСПРАВЛЕНО
- Описание:
  Обработчик `orbita:openFolder` вызывал `shell.openPath(folderPath)` без проверки, является ли путь каталогом. Если передать путь к файлу `.exe` или `.bat`, Windows запускает его.
- Решение:
  Добавлена проверка `fs.existsSync(folderPath) && fs.statSync(folderPath).isDirectory()`. Запуск файлов заблокирован.

[ИСПРАВЛЕНО] 12. Arbitrary File Deletion через `orbita:deleteTempFile`
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 3150-3160)
- Статус: ИСПРАВЛЕНО
- Описание:
  Метод `orbita:deleteTempFile` удалял любой файл по абсолютному пути через `fs.unlinkSync`, позволяя вредоносному коду удалять базы данных, ключи или файлы операционной системы.
- Решение:
  Путь проверяется через `path.resolve` и строго ограничен каталогами временных файлов (`app.getPath('temp')` и `os.tmpdir()`).

[ИСПРАВЛЕНО] 13. Неограниченное чтение произвольных файлов через `orbita:readFileAsDataURL`
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 3200-3235)
- Статус: ИСПРАВЛЕНО
- Описание:
  Метод `orbita:readFileAsDataURL` читал любой файл с диска и отдавал его содержимое в base64.
- Решение:
  Запрещено чтение чувствительных файлов и каталогов (.env, .key, .enc, .db, .sqlite, .ssh, .aws, исполняемых и конфигурационных файлов).

[ИСПРАВЛЕНО] 14. Неограниченное чтение произвольных файлов через `orbita:rustReadFileFast`
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 3094-3115)
- Статус: ИСПРАВЛЕНО
- Описание:
  Метод считывал любой файл на жестком диске через нативный модуль Rust без ограничений путей.
- Решение:
  Чтение ограничено пределами `userData` и временных папок кэша.

[ИСПРАВЛЕНО] 15. Чтение произвольных файлов через `orbita:readKeyFile`
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 2856-2866)
- Статус: ИСПРАВЛЕНО
- Описание:
  Метод читал любой файл на диске вместо ключей шифрования.
- Решение:
  Чтение строго ограничено файлами ключей (`.key` и `orbita.key`).

[ИСПРАВЛЕНО] 16. Отсутствие контроля навигации в окнах звонка и медиа (`callWindow`, `mediaWindow`)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 4550-4570, 4820-4840)
- Статус: ИСПРАВЛЕНО
- Описание:
  В окнах `callWindow` и `mediaWindow` не блокировались несанкционированные переходы и открытие сторонних окон.
- Решение:
  Добавлены обработчики `will-navigate` и `setWindowOpenHandler` с принудительным открытием внешних ссылок во внешнем браузере и блокировкой сторонних переходов.

[ИСПРАВЛЕНО] 17. Небезопасный биндинг сервера синхронизации на `0.0.0.0`
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 5130-5145)
- Статус: ИСПРАВЛЕНО
- Описание:
  `syncServer` слушал все сетевые интерфейсы (`0.0.0.0`), позволяя внешним устройствам в локальной сети (Wi-Fi) сканировать и фингерпринтить мессенджер.
- Решение:
  Сервер переведен на локальный интерфейс `127.0.0.1`.

[ИСПРАВЛЕНО] 18. Спавн PowerShell при обновлении ярлыков приложения
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 4020-4035)
- Статус: ИСПРАВЛЕНО
- Описание:
  В `updateLnk` производился вызов `powershell.exe` с формированием команды через склейку строк, что создавало риски инъекций и триггерило EDR/антивирусы.
- Решение:
  Удален запуск PowerShell, используется только штатный API Electron `shell.writeShortcutLink`.
