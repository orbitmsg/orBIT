ОТЧЕТ ПО АУДИТУ БЕЗОПАСНОСТИ И УЯЗВИМОСТЯМ ORBITA MESSENGER
================================================================================

[КРИТИЧЕСКИЙ] 1. Zero-Click RCE через XSS в окне кастомных уведомлений (RAT Vector)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 253-257), public/notification-window.html (строки 515-523)
- Описание:
  В `electron/main.ts` окно всплывающих уведомлений `notifWindow` создается с опаснейшей конфигурацией:
    nodeIntegration: true,
    contextIsolation: false
  При этом в `public/notification-window.html` поле `avatarUrl` вставляется в DOM без санитизации и экранирования:
    avatarHtml = `<img src="${avatarUrl}" alt="Avatar" onerror="..." />`;
  Если злоумышленник установит в качестве своего аватара пейлоад вида:
    x" onerror="require('child_process').exec('powershell -enc ...')
  и отправит любое текстовое сообщение жертве, то при всплытии уведомления на рабочем столе сработает обработчик onerror, имеющий прямой доступ к Node.js.
- Последствия:
  Скрытое выполнение произвольного кода (RCE) без клика со стороны пользователя (Zero-Click), мгновенная скрытая установка RAT/трояна.
- Рекомендация:
  Включить `contextIsolation: true`, выключить `nodeIntegration: false`, передавать данные только через строгий preload-скрипт, а в HTML использовать строгую санитизацию URL и безопасную установку атрибута через `.src = ...` без шаблонных строк HTML.

[КРИТИЧЕСКИЙ] 2. Запуск вредоносных бинарников без проверки при открытии файлов (1-Click RCE / RAT)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 1515-1556), src/components/chat/FileMessage.tsx (строки 185-187)
- Описание:
  При клике на файл во входящем сообщении чата вызывается IPC-метод `orbita:open-file` (или `downloads:open`).
  В `electron/main.ts` метод `orbita:open-file` сохраняет данные во временную папку и вызывает:
    await shell.openPath(filePath);
  Аналогично в `downloads:open` в `main.ts` вызывается `shell.openPath(full)`.
  В этих методах полностью отсутствует проверка расширений (в отличие от `downloads.ts`, где была `isDangerousExecutable`).
  В ОС Windows вызов `shell.openPath` для файлов .exe, .bat, .cmd, .vbs, .scr, .pif, .lnk запускает их на прямое исполнение с правами текущего пользователя без предупреждений.
- Последствия:
  Злоумышленник присылает жертве исполняемый файл (например, "photo.bat" или "contract.exe"), жертва нажимает "Открыть", после чего мгновенно запускается RAT/вредоносный софт.
- Рекомендация:
  Запретить прямое открытие потенциально опасных расширений (.exe, .bat, .cmd, .vbs, .js, .scr, .msi, .lnk, .ps1, .hta и т.д.). Для них вызывать только `shell.showItemInFolder(filePath)` и показывать диалог с предупреждением.

[КРИТИЧЕСКИЙ] 3. Path Traversal при скачивании и бэкапе (Arbitrary File Write / Persistence)
--------------------------------------------------------------------------------
- Файлы: electron/downloads.ts (строка 22), electron/main.ts (строки 2666-2680)
- Описание:
  1) В `electron/downloads.ts` в `saveToDownloads`:
     `const filePath = path.join(dir, fileName);`
     Имя `fileName` не очищается через `path.basename`. Если в имени передать последовательность вида `..\..\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\payload.bat`, файл будет сохранен в папку автозагрузки Windows.
  2) В `electron/main.ts` IPC-обработчик `orbita:saveBackupFile` принимает `folderPath` и `fileName` напрямую из рендерера и без валидации пишет данные по произвольному пути.
- Последствия:
  Запись произвольных файлов в файловой системе пользователя, закрепление вредоносного ПО в автозагрузке ОС.
- Рекомендация:
  Всегда оборачивать имя файла в `path.basename(fileName)`, нормализовать пути и проверять, что целевой каталог находится строго внутри разрешенной директории.

[КРИТИЧЕСКИЙ] 4. Небезопасное автообновление без проверки подписи и контрольных сумм (Insecure Update / RCE)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 5531-5655)
- Описание:
  Функция `downloadUpdateAsset` скачивает исполняемый файл `.exe` по ссылке из GitHub Releases и сохраняет в `%TEMP%`, после чего `orbita:quitAndInstallUpdate` запускает его через:
    spawn(downloadedInstallerPath, [], { detached: true, stdio: 'ignore' }).unref();
  При этом нет проверки хеша (SHA-256), проверки цифровой подписи Windows Authenticode или сертификата издателя.
- Последствия:
  При атаках Man-in-the-Middle (MitM), DNS-спуфинге, компрометации прокси или взломе репозитория пользователям автоматически доставляется и запускается любой сторонний бинарник.
- Рекомендация:
  Использовать стандартный механизм `electron-updater` с валидацией сигнатур кода (Authenticode) или сверять SHA-256 хеш с доверенным источником перед запуском.

[ВЫСОКИЙ] 5. Утечка любых локальных файлов через кастомный протокол `orbita-media://` (Local File Inclusion / Arbitrary File Read)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 48-60, 1263-1295)
- Описание:
  Схема `orbita-media` зарегистрирована с привилегиями `bypassCSP: true` и `corsEnabled: true`.
  В ее обработчике при отсутствии схемы `http://` / `https://` вызывается:
    const localPath = mediaUrl.startsWith('file://') ? fileURLToPath(mediaUrl) : mediaUrl;
    rawBuf = fastReadFile(localPath);
  Нет проверки выхода за пределы кэш-директории приложения.
- Последствия:
  Любой скрипт или загруженный контент может прочитать произвольные файлы на компьютере пользователя (конфигурации, приватные ключи, системные файлы Windows).
- Рекомендация:
  Ограничить чтение файлов строго папкой кэша приложения (`app.getPath('userData')/media`) и блокировать пути, выходящие наружу.

[ВЫСОКИЙ] 6. Небезопасные обработчики разрешений Electron (Blanket Permission Grant)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строки 5776-5781)
- Описание:
  Обработчики разрешений сессии безусловно возвращают `true` для всех запросов:
    session.defaultSession.setPermissionRequestHandler((_webContents, _permission, callback) => callback(true));
    session.defaultSession.setPermissionCheckHandler((_webContents, _permission) => true);
- Последствия:
  Любой фрейм, попап или сторонний веб-ресурс получает доступ к микрофону, вебкамере, геолокации и захвату экрана без подтверждения пользователя.
- Рекомендация:
  Проверять `origin` запрашивающего окна и разрешать доступ только для локальных доверенных URL (`file://` или внутренний бандл приложения).

[ВЫСОКИЙ] 7. Раскрытие мастер-ключа и приватных ключей E2EE в глобальном объекте `window`
--------------------------------------------------------------------------------
- Файлы: src/store/useAuthStore.ts (строки 489-490, 480-484)
- Описание:
  В конце файла стора аутентификации выполняется:
    (window as any).__ORBITA_AUTH_STORE__ = useAuthStore;
  Этот стор содержит незашифрованные поля: `masterSeed`, `identityKeyPair.privateKey`, `signedPreKeyPair.privateKey`, `oneTimePreKeys` и `recoveryKey`.
- Последствия:
  При малейшей XSS-уязвимости в интерфейсе злоумышленник одной строчкой кода в JS похищает все приватные криптографические ключи и историю переписки.
- Рекомендация:
  Удалить экспорт хранилища в глобальный объект `window` и никогда не выставлять приватные ключи наружу в глобальную область видимости.

[СРЕДНИЙ] 8. Отсутствие валидации URL в `orbita:fetchUrl` (SSRF)
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строка 3536, 3513-3534)
- Описание:
  IPC-обработчик `orbita:fetchUrl` делает сетевой запрос из Node.js без фильтрации локальных адресов (127.0.0.1, localhost, 169.254.169.254, адресов локальной сети 192.168.x.x / 10.x.x.x).
- Последствия:
  Возможность сканирования внутренней сети пользователя и обращений к локальным сервисам (SSRF).
- Рекомендация:
  Добавить фильтрацию приватных и loopback IP-адресов.

[СРЕДНИЙ] 9. Ослабление изоляции процессов в Chromium
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строка 43)
- Описание:
  При старте приложения передан ключ:
    app.commandLine.appendSwitch('disable-site-isolation-trials');
- Последствия:
  Снижается эффективность встроенной защиты Chromium (Site Isolation) от межсайтовых атак и атак типа Spectre.
- Рекомендация:
  Удалить этот флаг и оставить стандартную политику изоляции сайтов.

[СРЕДНИЙ] 10. Хардкод публичных API-ключей и идентификаторов сервисов в коде
--------------------------------------------------------------------------------
- Файлы: electron/main.ts (строка 73), src/services/channelService.ts (строка 48), src/services/groupService.ts (строка 44), api/index.js (строки 16-26)
- Описание:
  В коде захардкожены ключи Pusher, Supabase publishable keys и Cloudinary API Key.
- Последствия:
  Риск злоупотребления квотами сервисов и манипуляции ресурсами в случае отсутствия строгих RLS/политик на стороне серверов.
- Рекомендация:
  Вынести все параметры конфигурации исключительно в переменные окружения и настроить строгие лимиты на стороне облачных сервисов.
